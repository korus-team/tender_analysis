# DAR — сервис для анализа тендеров

Веб-приложение для отдела insight sales (департамент аналитических решений, КОРУС Консалтинг).
Помогает быстро находить релевантные тендеры и сокращает ручной просмотр нерелевантной выдачи:
собирает закупки, отсеивает непрофильные и мелкие, показывает подходящие с наглядными тегами и сроками.

Разрабатывается в рамках стажировки в КОРУС Консалтинг.

## Возможности

- **Импорт тендеров из Контур.Закупок** через Excel-выгрузку с дедупликацией, проверкой компаний, скорингом и сохранением в общей базе.
- **Отбор по профилю**: для коммерческих закупок размер компании проверяется по локальному подтверждённому справочнику, через открытую отчётность ГИР БО ФНС по ИНН, затем по названию и по дополнительному реестру названий. Подтверждённый оборот должен быть от 10 млрд ₽; неподтверждённые коммерческие компании в выдачу не попадают. Государственные закупки по обороту не фильтруются и не получают строку об объёме компании в карточке. Успешные проверки ФНС автоматически накапливаются в локальном CSV. Дополнительно используется классификация по типам закупок (данные/ДВХ, BI, лицензии, Big Data, ML, управление данными).
- **Наглядные теги**: тип закупки, коммерческая/государственная (44-ФЗ / 223-ФЗ / 615 ПП РФ), лицензии, приоритетная компания, «наиболее подходящее».
- **Сортировка по сроку подачи** по умолчанию, подсветка близких дедлайнов (красным при ≤ 3 днях, кроме лицензий; отдельно «Меньше N часов»).
- **Разделы**: Поиск, Приоритеты (приоритетные компании), Избранное (метки сотрудников и этапы), Нерелевантные (контроль качества подбора), Аналитика (воронка), Настройки.
- **Приоритетные компании** загружаются из `.xlsx`: система сама находит колонки с названием и ИНН среди других столбцов, исключает дубли и сопоставляет тендеры только по точному ИНН. Их тендеры не отбрасываются по порогу 10 млрд ₽.
- **Совместная работа**: регистрация/вход, «взять в работу» с видимой меткой сотрудника, уведомления, ручная корректировка релевантности.
- **Анализ документации**: в карточке тендера можно загрузить до 20 файлов TXT, MD, CSV, DOCX или PDF. Сервис сохраняет только результат, а не исходные документы; он отмечает риски, признаки ограничения конкуренции и, по запросу, рекомендации к коммерческому предложению.

Подробное описание того, что реализовано и что в планах — в документе с отчётом о разработке.

## Технологии

- Python, Flask, Jinja2
- SQLite
- HTML / CSS / немного JavaScript (серверный рендеринг)

## Запуск

1. Установить зависимости:
   ```bash
pip install -r requirements.txt
   ```
2. Запустить приложение:
   ```bash
   python app.py
   ```
3. Открыть в браузере адрес, который покажет консоль (обычно `http://127.0.0.1:5000`).

При первом запуске база данных `tenders.db` со всеми таблицами создаётся автоматически.
Чтобы наполнить её тендерами, загрузите на странице «Поиск» Excel-выгрузку Контур.Закупок.

## Настройка LLM API
Анализ документов и оценка тендеров используют общий API-ключ и общий OpenAI-совместимый API:
```env
# Адрес OpenAI-совместимого API.
# Если переменная не задана или оставлена пустой,
# то используется: https://api.openai.com/v1
OPENAI_BASE_URL=

# Общий API-ключ для анализа документов и оценки тендеров.
OPENAI_API_KEY=
```
Не добавляйте ключ в репозиторий.
### ИИ-анализ документов

Без ключа доступен локальный экспресс-анализ, чтобы можно было проверить интерфейс и сценарий загрузки. Для полноценного анализа скопируйте `.env.example` в `.env` и добавьте свой ключ:

```env
# модель для анализа документов
# при необходимости можно выбрать другую доступную вам модель
OPENAI_MODEL=gpt-5.6-luna
```
Тексты загруженных документов передаются в чужую API. Загруженные файлы сохраняются локально в папке `uploads/` (она исключена из Git), чтобы можно было открыть источник рядом с каждой рекомендацией.

### ИИ оценка тендеров
Чтобы включить нужно в .env файле установить переменные:
```
# для оценки тендеров используйте openai compatible api и настройте следующие параметры
# модель, которую следует использовать (например gpt-5.6-luna)
# примечание: модель для тендеров может отличаться от модели для документов 
OPENAI_TENDER_MODEL=
# флаг выкл/вкл (0 или 1)
USE_LLM_SCORING=0
```

## Структура проекта

- `app.py` — веб-слой: страницы, действия, авторизация, оформление данных.
- `integrations/` — активные интеграции с внешними источниками, включая Excel Контур.Закупок.
- `services/` — прикладные сервисы: приоритетные компании и формирование запросов документов.
- `observability/` — единая настройка серверного логирования.
- `tools/` — вспомогательные консольные инструменты.
- `directions.py` — классификатор типа закупки.
- `company_size.py` — проверка размера компании-заказчика (порог 10 млрд ₽).
- `data/russian_companies_mega_registry_with_it.txt` — дополнительный реестр точных названий крупных компаний; используется только при полном совпадении нормализованного названия.
- `storage.py`, `scoring.py`, `icp_config.py` — модули хранения, оценки и конфигурации профиля.
- `templates/` — HTML-шаблоны страниц.
- `schema.sql` — структура базы данных (для справки; база создаётся автоматически при запуске).
