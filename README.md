# Ассистент для анализа тендеров

Локальный сервис для тендерного отдела ИТ-компании: **собирает тендеры с rostender.info,
оценивает их релевантность вашему бизнесу, ранжирует и даёт вести их в работе** —
статусы, сроки, воронка. Всё работает на вашем компьютере, запускается одной командой,
интерфейс — в браузере.

Поток: **сбор → нормализация и дедупликация → оценка (профиль + тема) → рабочее место**.

---

## Быстрый старт

1. Открой папку как проект в PyCharm. Согласись создать виртуальное окружение (venv).
2. Установи зависимости (терминал внутри PyCharm):
   ```
   pip install -r requirements.txt
   ```
   Если собираешь через VPN — дополнительно `pip install pysocks` (поддержка SOCKS-прокси).
3. Запусти `app.py` (правой кнопкой → Run 'app').
4. Открой в браузере `http://127.0.0.1:5000`.

Дальше всё делается в интерфейсе. Сам интерфейс интернета не требует и работает за любым
прокси/VPN; интернет нужен только кнопке «Собрать тендеры» (она ходит на rostender).

---

## Четыре экрана (меню сверху)

**Список** — основное рабочее место. Тендеры с баллом релевантности, отсортированные по
нему, постранично по 20. Здесь же:
- кнопка **«Собрать тендеры»** — парсит сайт и добавляет новые (см. «Сбор»);
- кнопка **«Обогатить N»** — подтягивает данные с детальных страниц (см. «Обогащение»);
- поле **«Тема / что ищем»** и **фильтры** (статус, категория, регион, мин. балл);
- у каждого тендера — смена статуса и удаление.

**Дедлайны** — тендеры с близким закрытием подачи, от самого срочного. Окна ≤3/7/14/30 дней
или все будущие; цветом выделена срочность. Показаны только тендеры в работе — просроченные
и завершённые скрыты.

**Профиль** — настройка того, что считается выгодным для вашей компании (бюджет, регионы,
ключевые слова, штрафы, стоп-слова, веса факторов) прямо в интерфейсе, с пояснением к каждому
полю. После сохранения баллы **пересчитываются у всех тендеров сразу**.

**Журнал** — воронка (сколько тендеров на каждой стадии, доля побед, всего смен статуса) и
история смены статусов: когда, у какого тендера, с какого статуса на какой.

---

## Как считается балл релевантности

У балла две настраиваемые стороны, а ползунок на «Списке» задаёт их баланс:

- **Профиль** (страница «Профиль») — «умная» оценка выгодности для компании: профильные работы
  (разработка, внедрение, ИИ) поднимают балл, перепродажа лицензий и поставка железа —
  понижают; учитываются бюджет, регион, срок. Жёсткие стопы (мебель, просрочка, бюджет вне
  диапазона) дают 0.
- **Тема** (поле «Тема / что ищем») — быстрый ручной поиск: совпадение слов вашего запроса с
  тендером, видно какие слова совпали.

Если тема пустая — балл на 100% по профилю. Если вписана — **итог = (вес темы)×тема +
(остальное)×профиль** (по умолчанию 60/40, регулируется ползунком). В причине под тендером
всегда видна разбивка «Тема … · Профиль … · Итог …».

Статусы тендера: Новый → На рассмотрении → В работе → Выиграли / Проиграли / Отклонён.
Статус живёт отдельно от сбора и не сбрасывается при повторном парсинге.

## Сбор тендеров

Кнопка «Собрать тендеры» парсит несколько сервисных категорий rostender (разработка ПО,
услуги программирования, разработка ИС) и работает **инкрементально**: добавляет только новые
тендеры и останавливается, дойдя до уже известных. Привязки к числу страниц нет; есть только
предохранитель (`MAX_PAGES` в `main.py`). Дубликаты убираются по номеру тендера.

Категории задаются списком `CATEGORY_PATHS` в `rostender_parser.py` — их можно менять/дополнять.

---

## Обогащение (кнопка «Обогатить N»)

Заходит на страницу каждого тендера (выборочно — сначала самые релевантные, пачкой на выбор) и
добавляет то, чего нет в списке:
- **номер ЕИС и ссылку на официальный сайт госзакупок**, где документация бесплатна для всех
  (rostender свои документы прячет за регистрацией);
- **реальную цену** там, где в списке был прочерк; **аванс**;
- **срок исполнения контракта**, **способ размещения**, признак **«только СМП»** (можно ли
  вам участвовать).

Ограничения источника (для анонимного доступа): имя заказчика rostender скрывает везде;
полный текст описания лежит внутри файла «Описание объекта закупки», а не на странице — поэтому
даётся ссылка на сам файл через ЕИС.

## Файлы данных (создаются при работе)

- `tenders.db` — база SQLite: все тендеры, статусы, история статусов, данные обогащения.
  Накапливается и дедуплицируется между запусками. Открывается любым SQLite-браузером или
  прямо в PyCharm (Database → New → SQLite).
- `icp_active.json` — активный профиль (то, что вы настроили на странице «Профиль»).
  Если файла нет — берётся профиль по умолчанию из `icp_config.py`.
- `tenders_raw.json`, `tenders_scored.json` — снимок последнего сбора (перезаписываются).

## Структура проекта

| Файл | Что делает |
|---|---|
| `app.py` | Веб-приложение (Flask): все страницы и действия |
| `templates/index.html` | Страница «Список» |
| `templates/deadlines.html` | Страница «Дедлайны» |
| `templates/settings.html` | Страница «Профиль» |
| `templates/history.html` | Страница «Журнал» |
| `rostender_parser.py` | Парсер сайта + инкрементальный сбор |
| `scoring.py` | Оценка: профиль (`score_tender`) и тема (`theme_score`) |
| `icp_config.py` | Профиль по умолчанию + чтение/запись активного профиля |
| `storage.py` | База SQLite: хранение, дедупликация, статусы, история, обогащение |
| `enrich.py` | Обогащение с детальных страниц (ЕИС, цена, аванс, СМП) |
| `main.py` | Сбор (`run_ingest`) и пересчёт баллов (`rescore_all`) |
| `manage.py` | Консольное управление статусами (быстрый вариант без браузера) |
| `llm_classifier.py` | Опциональный ИИ-слой оценки (по умолчанию выключен) |
| `requirements.txt` | Зависимости |
| `test_fixture.html` | Слепок для офлайн-проверки парсера |

`main.py`, `enrich.py`, `manage.py` можно запускать и отдельно из консоли, но для обычной
работы достаточно `app.py`.

## Надёжность и легальность

- Парсер вежливый: паузы между запросами, User-Agent, повторные попытки. Селекторы построены
  на устойчивых текстовых подписях сайта; если вёрстка поменяется — правится функция
  `find_cards()` в `rostender_parser.py`.
- У rostender есть RSS и страница выгрузки — для боевого продукта это стабильнее и легальнее
  парсинга HTML (см. ТЗ). Перед регулярным сбором стоит свериться с правилами сайта.
- Первоисточник тендеров — ЕИС (zakupki.gov.ru); туда и ведут ссылки на документы.
